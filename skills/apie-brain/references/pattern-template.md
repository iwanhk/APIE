# Pattern Template

Follow [APIE Pattern Schema v1](schemas.md). A pattern is a repeatable mechanism — not a single product's feature.

```markdown
---
id: pattern-id
type: pattern
name: Pattern Name
status: established | emerging | hypothesis
tags: [tag1, tag2]
last_updated: YYYY-MM-DD
---

# Pattern Name

## Definition
The mechanism, precisely. What repeats across instances?

## Purpose
The strategic job this pattern does.

## Problem
The underlying problem it solves.

## When To Use
Concrete preconditions.

## When NOT To Use
Concrete conditions where it is wrong or harmful.

## Examples
At least two products, each with the mechanism used.

## Engineering
Approaches, data signals, cold start, metrics.

## UX
Explainability, controls, serendipity vs relevance, cadence.

## Business
How it creates value.

## Cross-Domain Transfers
Candidate domains or links to cross-domain files.

## Pitfalls
Known failure modes.
```
